\begin{abstract}
This document describes CPPTAI V2.0md, a refactoring of the CPPTAI framework toward deterministic and auditable experimentation. The main contributions are: (i) a canonical schema for run artifacts, (ii) modular phase execution with explicit phase outputs, (iii) YAML-based configuration for reproducible suites, (iv) a deterministic cache layer enabling offline replay, and (v) CI automation for continuous evaluation.
\end{abstract}

\section{Motivation}
The primary objective of CPPTAI V2.0md is reproducibility: given a repository commit, a third party should be able to execute the suite and obtain the same benchmark logs, metrics, and figures (or a controlled approximation in strictly offline mode). This design addresses drift introduced by external APIs and remote datasets, and supports experimental auditing via structured artifacts.

\section{System Design}
\subsection{Module Contracts}
The framework is organized as follows:
\begin{itemize}
  \item \texttt{cpptai/types.py}: canonical dataclasses (\texttt{RunConfig}, \texttt{RunArtifact}, \texttt{PhaseOutput}, \texttt{BenchmarkItem}, \texttt{SolutionState}).
  \item \texttt{cpptai/phases/}: phase modules exposing \texttt{run(state, config)} for Phase I--V.
  \item \texttt{cpptai/pipeline\_v2.py}: suite runner producing structured JSON artifacts per run.
  \item \texttt{cpptai/io/cache.py}: deterministic cache for external connector inputs/outputs.
  \item \texttt{scripts/run\_suite.py}: YAML-configured driver for v2 runs and benchmarks.
\end{itemize}

\subsection{Canonical Artifact Schema}
Each run produces \texttt{run\_\{uuid\}.json}, a fully structured artifact containing configuration, phase-by-phase inputs/outputs, entropy proxies, provenance, verification outcomes, and failure metadata.

\subsection{Deterministic Modes}
The suite supports online, cached, and offline execution. In offline mode, external calls are disabled and cached responses are replayed if present; otherwise, the pipeline degrades gracefully to deterministic stub outputs. The cache is keyed by normalized request payloads to enable stable replay across machines.

\section{Benchmark Integration}
\subsection{Dataset Loading}
Benchmark datasets are loaded using HuggingFace \texttt{datasets} in streaming mode when available, with robust fallbacks to deterministic synthetic stubs when a dataset is inaccessible.

\subsection{Unified Runner}
The command \texttt{python scripts/run\_suite.py --config configs/offline.yaml} executes a complete v2 run plus the benchmark suite in offline mode, storing structured artifacts under the configured output directory.

Continuous evaluation is enforced via GitHub Actions, running unit tests and an offline v2 smoke run on each push and pull request.
